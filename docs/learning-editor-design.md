# 学习中心文档编辑与划词交互设计

## 目标

学习中心的课程文档继续以仓库中的 Markdown 为默认内容来源，同时允许管理员在页面内编辑个人版本，并同步到服务端数据库。非编辑模式下，用户可以选中文档中的文字，使用浮动工具条进行标注或请求 AI 解释。

## 内容来源与覆盖关系

- 仓库 Markdown：课程的初始版本、可回滚的基准版本。
- 数据库文档覆盖：管理员编辑后的版本，按 `lessonId` 保存。
- 页面读取：优先使用数据库覆盖内容；没有覆盖时回退到仓库 Markdown。
- 编辑器保存：使用防抖自动保存，并提供明确的“已保存/保存中/保存失败”状态。
- 当前单管理员方案不做多人协同和版本合并；后续扩展多用户时再引入 revision、作者和冲突处理。

## 编辑模式

在学习中心顶部更多菜单中提供“编辑文档”。进入编辑模式后：

1. 左侧课表、顶部课程标题和底部学习导航保持不变，减少模式切换成本。
2. 中间阅读区域切换为 Markdown 编辑器，左侧编辑、右侧预览；窄屏时切换为编辑/预览 Tab。
3. 顶部显示保存状态、恢复仓库版本和退出编辑按钮。
4. 保存前保留本地草稿，网络失败时不丢失输入；恢复仓库版本必须二次确认。
5. 编辑模式不启用划词工具，避免选择文本与输入行为冲突。

## 非编辑模式与划词工具条

用户在渲染后的 Markdown 中选中文本后：

- 选择范围小于 2 个字符不显示工具条。
- 工具条贴近选择区域显示，超出窗口边缘时自动翻转或收缩。
- 工具条包含：颜色标注、添加笔记、AI 解释、复制。
- 颜色只使用少量语义色：黄色“待理解”、绿色“已掌握”、红色“易错”；默认不改变正文可读性。
- 已有标注再次点击时显示编辑/删除操作。
- 移动端使用底部操作面板，不依赖精确悬浮定位。

## 标注数据

标注至少保存：`lessonId`、原文引用、字符范围、颜色、笔记、创建和更新时间。第一版建议保存引用文本而不是只保存 DOM offset，因为 Markdown 内容编辑后 offset 会失效；加载时通过引用文本和附近上下文重新定位，无法定位时显示“原文已变化”，不静默丢弃。

## AI 解释

点击“AI 解释”后：

1. 保留原文选中状态和工具条视觉锚点。
2. 在右侧 AI 助教中创建带引用上下文的提问，而不是新建独立聊天窗口。
3. 提问内容包含课程、当前步骤、选中文本和“用前端工程师能懂的类比解释”。
4. AI 请求期间工具条显示加载状态，避免重复触发。
5. 失败时显示可重试操作，不影响原有标注。

## 数据接口建议

- `GET /api/lesson-documents/:lessonId`：读取覆盖内容和更新时间。
- `PUT /api/lesson-documents/:lessonId`：保存 Markdown 覆盖内容。
- `DELETE /api/lesson-documents/:lessonId`：删除覆盖，恢复仓库版本。
- `GET /api/lesson-annotations/:lessonId`：读取标注。
- `PUT /api/lesson-annotations/:lessonId`：保存该课程全部标注。

## 数据库建议

第一版可以使用两张表：

- `lesson_documents`：`lesson_id`、`content`、`updated_at`。
- `lesson_annotations`：`lesson_id`、JSON 标注数组、`updated_at`。

接口必须继续走管理员 Session；不接受客户端提交的 `userKey`。Markdown 和标注都需要长度上限，避免把超大文档写入 SQLite。

## 分阶段实现

1. 先实现文档覆盖读取/保存和编辑模式，验证数据库同步、恢复基线、离线草稿。
2. 再实现划词工具条和颜色标注，先不接 AI，验证定位、移动端和内容变化后的降级。
3. 最后接入 AI 助教，将选中文本转换为现有聊天消息，避免维护第二套流式聊天系统。
4. 最终补充标注删除、冲突提示、键盘操作和完整的移动端体验。

## 设计原则

- 阅读优先：默认页面仍是干净的 Markdown 阅读器，不显示编辑控件。
- 可逆：任何编辑和标注都能恢复或删除。
- 不打断：AI 解释复用右侧助教，不弹出遮挡正文的大窗口。
- 可解释：保存状态、引用失效和 AI 错误都给出明确反馈。
- 先稳定数据模型，再增加高频交互，避免把编辑器、批注和聊天一次性耦合。

该文档是后续实现规则，不代表所有能力已经上线。
