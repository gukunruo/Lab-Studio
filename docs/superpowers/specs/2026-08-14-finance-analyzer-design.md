# 金融分析模块设计文档

> 日期：2026-08-14
> 目标：在 Lab Studio 中新增一个以 AI 分析为核心的金融分析模块（股票 + 基金），支持关键词/代码/板块/ETF/指数搜索、选标的、K 线与技术指标可视化、量价关系分析、AI 走势推演与量化辅助。

---

## 1. 产品定位与范围（金融专家视角）

### 1.1 这是什么

一个**面向个人研究的金融分析工作台**，不是交易终端。核心价值是：把散落在公开行情源里的数据，整理成「看得懂、算得清、推得动」的分析视图，并让 AI 在真实数据之上做结构化研判。

三条设计原则：

1. **AI 是重点，数据是底座。** 所有 AI 分析都基于服务端拉取的真实行情数据，AI 拿到的是清洗后的结构化数据（K 线、指标、量价），而不是用户口头描述。这避免 AI「编造行情」。
2. **分析可解释，结论可复核。** AI 的每个判断都附带它引用的数据依据（均线位置、MACD 状态、量比等），用户可以对着图表复核。不输出「投资建议」，输出「证据 + 推演 + 风险」。
3. **合规与安全优先。** 模块默认且强制附带免责声明，AI 提示词内禁止承诺收益、禁止「保证/必涨/稳赚」类表述，所有数据仅作研究参考。

### 1.2 覆盖的资产类型

| 类型 | 中文 | 数据源 | 展示 |
|---|---|---|---|
| AStock | A 股股票 | 东财 K 线（前复权） | 蜡烛图 + 指标 + 量价 |
| Index | 指数（上证/深成/创业板等） | 东财 K 线 | 同上 |
| Fund | 场内基金（ETF/LOF） | 东财 K 线 | 同上 |
| BK | 行业/概念板块 | 东财板块指数 | 同上 |
| OTCFUND | 场外基金（开放式） | 天天基金历史净值 | 净值曲线 + 涨跌幅 |

搜索统一走东财 `searchapi`，返回的 `Classify` 字段区分上述类型，路由到对应数据源。

### 1.3 量化能力边界（第一期）

技术指标计算**在前端纯函数完成**（不引第三方库，保证可读与可控）：

- 均线：MA5/10/20/60（可切换）
- 指数平滑：EMA（用于 MACD）
- MACD：DIF/DEA/柱（12,26,9）
- RSI：6/12/24
- KDJ：9,3,3
- BOLL：20,2（中轨/上轨/下轨）
- 量价关系：量比（当日量 / 5 日均量）、放量/缩量标注、量价配合度（价涨量增/价涨量缩等）

指标数值会**同时喂给 AI**，让 AI 做「指标组合 + 走势形态 + 量价验证」的综合推演，而不是 AI 自己心算指标。

## 2. 数据源逆向结论（已实测验证）

### 2.1 搜索（东财 suggest）

```
GET https://searchapi.eastmoney.com/api/suggest/get
    ?input=<关键词>&type=14&token=D43BF722C8E33BDC906FB84D85E326E8&count=10
Headers: User-Agent(浏览器), Referer: https://www.eastmoney.com/
```

返回 `QuotationCodeTable.Data[]`，关键字段：

- `QuoteID`：如 `1.600519`（secid，K 线用）
- `Code`：如 `600519` / `BK0896` / `110022`
- `Name`：名称
- `Classify`：`AStock` | `Index` | `Fund` | `BK` | `OTCFUND`
- `SecurityTypeName`：`沪A` / `指数` / `基金` / `板块` …
- `MktNum`：市场号

已实测：`510300`→Fund(ETF)、`上证指数`→Index、`白酒`→BK、`000001`→AStock(平安银行)、`110022`→OTCFUND 均正确。

### 2.2 K 线（东财 push2his，股票/指数/ETF/板块通用）

```
GET https://push2his.eastmoney.com/api/qt/stock/kline/get
    ?secid=<QuoteID>&klt=101&fqt=1&lmt=<N>&end=20500101
    &fields1=f1,f2,f3,f4,f5,f6
    &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
Headers: User-Agent(浏览器), Referer: https://quote.eastmoney.com/
```

- `klt`：101=日线，102=周线，103=月线
- `fqt`：1=前复权（推荐），0=不复权
- `end=20500101` 表示取到最新
- 返回 `data.klines[]`，每行是逗号分隔字符串，字段序：
  `f51=日期, f52=开, f53=收, f54=高, f55=低, f56=成交量(手), f57=成交额, f58=振幅%, f59=涨跌幅%, f60=涨跌额, f61=换手率%`

### 2.3 场外基金历史净值（天天基金）

```
GET https://api.fund.eastmoney.com/f10/lsjz
    ?fundCode=<代码>&pageIndex=1&pageSize=<N>
Headers: User-Agent(浏览器), Referer: https://fundf10.eastmoney.com/
```

返回 `Data.LSJZList[]`，关键字段：

- `FSRQ`：净值日期
- `DWJZ`：单位净值
- `LJJZ`：累计净值
- `JZZZL`：日涨跌幅（%）

已实测：`110022`（易方达消费）返回完整净值序列。

### 2.4 板块列表（可选，弱依赖）

东财板块列表接口在本沙箱环境被限流，且板块指数 K 线与个股共用同一 `push2his` 接口。第一期**不单独做板块列表页**，板块通过搜索关键词命中（如搜「白酒」直接出现 `BK0896` 板块）。板块的 K 线用 `secid=90.BK0896` 走同一 K 线接口。

### 2.5 关于实时行情与限流

- 实时报价接口 `push2.eastmoney.com/api/qt/stock/get` 在本沙箱出口 IP 上被限流（「Empty reply from server」），但这是**沙箱 IP 限流，非接口失效**；用户本地运行服务端代理不受影响。
- 设计上：**最新价/最新涨跌幅一律从 K 线最后一根 bar 推导**（f53 收盘价、f59 涨跌幅），不依赖实时报价接口，保证「收盘后」与「盘中」都能稳定工作。
- 服务端对第三方接口统一加浏览器 UA + Referer，并做**内存缓存（TTL 60s）**，避免频繁请求触发风控。

### 2.6 服务端代理的必要性

前端直连东财会遇到 CORS 与 Referer 限制。所有第三方请求经服务端代理：

- 统一注入 UA/Referer，规避风控
- 内存缓存，降低上游压力
- 收敛数据清洗逻辑（K 线字符串切分、字段映射）到一处

## 3. 架构设计（架构师视角）

### 3.1 分层

```
┌─────────────────────────────────────────────────┐
│  Vue 前端（src/apps/finance/）                    │
│  index.vue: 页面编排（搜索/图/指标/AI 面板）       │
│  - chart: SVG 蜡烛图 + 成交量 + 指标叠加          │
│  - indicators.ts: MA/EMA/MACD/RSI/KDJ/BOLL/量价   │
│  - ai.ts: 复用 /api/ai/chat 流式                  │
└───────────────────┬─────────────────────────────┘
                    │ fetch /api/finance/*
┌───────────────────▼─────────────────────────────┐
│  Node 服务端（server/finance.ts 模块）             │
│  - /api/finance/search     搜索（东财 suggest）    │
│  - /api/finance/kline      K 线（push2his）        │
│  - /api/finance/fund/nav   场外基金净值（天天基金） │
│  - 内存缓存 + UA/Referer + 字段清洗                │
└───────────────────┬─────────────────────────────┘
                    │ fetch
        ┌───────────┼───────────────────────────┐
        │           │                           │
   eastmoney     天天基金                AI 网关(复用 /api/ai/chat)
   searchapi   api.fund.eastmoney
   push2his
```

### 3.3 前端模块划分

```
src/apps/finance/
  meta.ts          应用注册（title/description/tags/date）
  index.vue        页面编排：搜索栏 + 左侧图区 + 右侧 AI 面板
  doc.md           应用说明（免责声明 + 用法）
  indicators.ts    技术指标纯函数（无 UI 依赖，可单测）
  chart/           图表组件（可选拆子组件）
    KlineChart.vue SVG 蜡烛图 + 成交量 + 指标叠加
  useFinance.ts    组合式函数：搜索/选标的/取数/状态机
```

技术选型：图表**手写 SVG**（不引 ECharts/轻量库）。理由：项目是自包含应用、无图表库依赖、K 线 + 均线 + 指标叠加用 SVG path 即可高质量实现且完全可控，避免新增重依赖。蜡烛图 + 成交量双区 + 均线 + BOLL + MACD/RSI/KDJ 子区都用 SVG。

### 3.4 AI 分析管线

AI 不直连行情，而是**服务端把清洗好的数据交给前端，前端拼装成结构化的「数据快照」注入提示词**：

```
用户点「AI 分析」→
  前端从当前选中标的 + 已算指标，生成 data snapshot：
    - 标的名、代码、类型、最近 N 根 K 线的开高低收量额
    - 现价、区间涨跌、均线排列、MACD/RSI/KDJ/BOLL 状态、量价配合
  → 组装 system prompt（金融分析师角色 + 合规约束 + 免责声明）
  → 复用 /api/ai/chat（SSE 流式）
  → 前端 Markdown 渲染，逐字流式显示
```

AI 输出固定四段结构（由 system prompt 约束）：**走势研判 → 量价关系 → 技术指标验证 → 推演与风险**。每段要求给出数据依据。

## 4. UI / 交互设计（设计专家视角）

### 4.1 设计基调

- 复用现有设计系统：zinc 中性底 + teal 单强调色，`--radius-*` / `--space-*` / `--font-mono` 全部沿用。
- 金融数据惯例：**涨用红、跌用绿**（中国市场惯例），与强调色 teal 解耦——行情颜色是语义色，不是品牌色。浅色主题用 `#dc2626`（涨）/ `#16a34a`（跌）；深色主题用 `#f87171` / `#4ade80`。这些作为模块内局部变量，不污染全局 token。
- 密度：中等偏数据型（`VISUAL_DENSITY` 偏 cockpit 但克制），图表区占主导，AI 面板右侧固定宽度。
- 排版：数字一律 `var(--font-mono)`，中文标签用 `var(--font-sans)`。

### 4.2 布局（桌面优先）

```
┌──────────────────────────────────────────────────────────┐
│  搜索栏： [输入关键词/代码/板块]  🔍   (下拉建议列表)        │
├───────────────────────────────┬──────────────────────────┤
│  标的信息条：名称 代码 类型       │  AI 分析面板 (宽 ~360px)   │
│  ├───────────────────────────┤  ┌──────────────────────┐ │
│  │  周期切换: 日/周/月           │  │  标题 + 免责声明      │ │
│  │  指标开关: MA/MACD/RSI/KDJ/ │  │  [开始分析] 按钮      │ │
│  │           BOLL              │  │  (流式 Markdown)     │ │
│  ├───────────────────────────┤  │  走势研判             │ │
│  │  K 线主图 (蜡烛+均线+BOLL)   │  │  量价关系             │ │
│  │  成交量副图                  │  │  指标验证             │ │
│  │  MACD / RSI / KDJ 子区       │  │  推演与风险           │ │
│  └───────────────────────────┘  └──────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

移动端（≤ 720px）：图表与 AI 面板纵向堆叠，AI 面板变底部可滚动区。

### 4.3 交互状态

- **空状态**：搜索框聚焦提示「输入股票/基金代码、名称或板块关键词」；未选标的前图表区显示引导插画（一个简单的 K 线轮廓 + 提示文字）。
- **加载态**：搜索下拉显示骨架行；K 线加载显示图表区骨架（灰色蜡烛轮廓）。
- **错误态**：上游限流/失败时，图表区显示内联错误 + 「重试」按钮，文案「数据源暂时不可用，请稍后重试」。
- **搜索防抖**：输入 250ms 防抖；键盘 ↑↓ 选择、Enter 确认、Esc 关闭下拉。
- **标的切换**：选中即拉 K 线；AI 面板内容清空（提示重新分析）。
- **AI 流式**：逐字渲染，可停止；分析中禁用「开始分析」按钮显示「生成中…」。

### 4.4 免责与合规（强制 UI）

- AI 面板顶部固定免责声明：「本分析基于公开历史行情与 AI 研判，仅供研究参考，不构成任何投资建议。市场有风险，决策需谨慎。」
- AI 结果末尾自动附同样声明。

## 5. 安全与合规约束

1. 所有第三方数据请求走服务端代理，前端不暴露上游域名细节（返回体不携带 token/Referer 细节）。
2. 输入校验：`secid` 必须是 `市场.代码` 格式且代码只含字母数字；`klt` 白名单 `101/102/103`；`limit` 上限 500；基金代码仅数字。
3. AI 提示词内嵌合规约束：禁止承诺收益、禁止「必涨/稳赚/保证」，必须输出风险提示，必须声明「非投资建议」。
4. 不缓存任何账号类凭证；行情缓存为纯公开数据，无敏感信息。

## 6. 测试与验收

- **类型检查**：`pnpm type-check` 通过。
- **构建**：`pnpm build` 通过。
- **指标引擎**：对 MA/MACD/RSI/KDJ/BOLL 各写关键断言（黄金交叉、超买超卖边界、标准差计算）。
- **数据链路**：搜索（股票/ETF/指数/板块/场外基金各一例）、K 线字段映射、场外净值字段映射。
- **UI**：搜索→选标的→出图→切周期→切指标→AI 流式分析→停止，全链路手测。
- **合规**：AI 输出含免责声明与风险提示。
