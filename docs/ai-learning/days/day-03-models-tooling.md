# Day 03 · 模型选型与工具链

> Phase 0 · 地基 · ~60 min  
> 标签：`models` `tooling` `cursor` `cost` `routing`  
> 前置：Day 01–02

## 今日目标

建立「任务 → 模型 / 模式」决策表。理解旗舰/中档/轻量/推理模型各自适合什么、Auto 路由替你做了什么决定、以及为什么 Agent 任务会贵一个数量级。

## 为什么重要

用错模型 = 又贵又慢还更蠢，或反过来该深度推理却用了轻量补全。你已经多模型切换（Cursor Auto、Gemini、ChatGPT、Claude、GLM），今天把"凭感觉切"升级成"按轴选"。

## 核心概念

### 1. 六条能力轴

选模型就是在这几条轴上找最匹配的，没有"全能最优"：

| 轴 | 含义 | 你的体感 |
|---|---|---|
| 智能 / 推理 | 复杂重构、架构权衡、难 bug | 同样 prompt 出更靠谱的方案 |
| 速度 | 补全、小改、格式化 | 首 token 快、吐字快 |
| 上下文长度 | 能吞多大仓库片段 / 长文档 | 长不等于"能记住"，见下 |
| 工具调用稳定性 | Agent 循环靠谱否 | 会不会乱编 tool 参数 |
| 多模态 | 看图、读设计稿、读报错截图 | 能不能直接喂图片 |
| 价格 | 按 token 计 | Agent 会放大几十倍 |

### 2. 模型分档（按用途，非按厂商）

- **旗舰**：最难推理、架构决策、跨文件大重构。贵、慢，但少返工。
- **中档**：日常 80% 任务（改组件、读报错、写函数）。性价比最优。
- **轻量**：补全、小改名、格式化、分类路由。快且便宜。
- **推理模型**：显式"思考"再答（类似 Day 02 的 CoT（Chain of Thought，思维链）内建）。适合数学/多步推理，但慢且烧 token，简单任务别用。

**前端类比**：像选渲染策略——旗舰=SSR 重计算、中档=常规组件、轻量=纯静态、推理模型=离线构建。按场景选，不全家桶。

### 3. 长上下文 ≠ 全记得

厂商标 200k/1M 窗口，不等于把整仓塞进去就都能用。实证有 **"lost in the middle"**：长文档中间的内容召回率低于头尾。所以：

- 大上下文是"能放下"，不是"一定关注"
- 真要精准答，仍要靠**检索**先筛出相关片段（RAG（Retrieval-Augmented Generation，检索增强生成），Day 11–12），而不是赌模型自己从百万 token 里捞
- 近因偏好：末尾内容影响力最大（Day 02 已用——硬约束放末尾）

### 4. 模式：Chat / Agent / Auto

- **Chat**：你问它答，单轮或少量多轮。最省。
- **Agent / Code**：读文件、改文件、跑命令、多步自循环。每次循环都烧 token。
- **Auto 路由**：系统替你挑模型。省心，但要知道：它可能偏保守（总用贵模型防出错）或偏激进（轻量模型扛不住）。**对你：学习阶段关掉 Auto、手动切，体感每条轴；上线再开 Auto 省心。**

### 5. 经验决策表（按你体感改）

| 任务 | 倾向 |
|---|---|
| 重命名、改文案、小 UI | 轻量 / Auto |
| 跨文件重构、根因分析 | 旗舰 + Agent |
| 读报错堆栈 | 中强即可，关键是塞对上下文 |
| 看截图还原 UI | 多模态 |
| 长文档整理 | 先检索分片，别裸塞 |
| 探索未知库 API | 中强 + 官方文档检索 |
| 数学/多步推理 | 推理模型 |

### 6. 工具链分工与成本直觉

- **Cursor**：仓库内改代码、`@` 引用文件、Rules/Composer。
- **Claude Code 等 CLI Agent**：终端向、脚本、批量、git 操作。
- **网页 Chat**：纯概念学习、无仓库时讨论、跑不了代码时。
- **API**：产品内嵌智能，要自己管密钥、限流、观测（Day 07+）。

**成本直觉**：一次 Agent 任务 = 几十上百次补全的 token。贵的不是"问一句"，是"让它自己转很多圈"。所以：

- 任务能用 Chat 一轮解决，别开 Agent
- Agent 转圈要有终止条件，别无限循环
- 上线前用 Day 22 的成本观测验证

## 动手练习（30–40 min）

1. **复盘**：列你过去一周真实用 AI 的 5 个任务，标"实际用了什么模型"和"若重来会换什么"。
2. **对照**：同一小任务（给某 Vue 组件加 loading）分别用轻量与旗舰各做一次，记录：耗时、改动质量、是否过度工程。
3. **产出**：写一张属于你的「默认路由表」贴在笔记或项目 Rule 注释里（任务类型 → 模型/模式）。
