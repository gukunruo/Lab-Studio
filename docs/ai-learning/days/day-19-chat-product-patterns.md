# Day 19 · Chat 产品交互模式

> Phase 3 · 产品与工程 · ~60 min  
> 标签：`product` `chat-ux` `patterns` `trust`  
> 前置：Day 18（流式 UI）、Day 12（RAG 引用）  
> 定位：Chat 不只是气泡。认识引用/追问/工具状态/空态/历史等模式，并学会克制做减法。

## 今日目标

能区分主路径与增强、有一版克制的线框、知道引用对信任的价值、能识别"功能堆叠但主路径不清"的反模式。

## 为什么重要

AI 产品差经常差在交互堆叠：功能很多，主路径不清。前端负责人的价值是做减法——Lab-Studio 本身就是"一屏一事"的克制美学。这课把 Chat 产品的常见模式摆出来，让你**有意选择**而不是全堆上。

## 核心概念

### 1. 主路径优先

用户任务永远是：**问清 → 得到可信答案 → 可继续或可复制走**。其它都是增强。首屏只服务主路径，增强按需加。

### 2. 常见模式（选型，不是全上）

| 模式 | 何时要 | 何时别加 |
|---|---|---|
| 引用 / 脚注 | RAG（Retrieval-Augmented Generation，检索增强生成）、合规场景 | 纯闲聊 |
| 建议追问 | 探索型助手 | 任务型（填表式） |
| 工具进度条 | Agent / MCP（Model Context Protocol，模型上下文协议）多步 | 单次调用 |
| 编辑重发 | 调试 Prompt、纠错 | 一次性问答 |
| 分支对话 | 高级用户/研究 | 成本高、复杂度高 |
| 多模态输入 | 真有图/文件场景 | 没场景别加 |
| 会话历史 | 回顾续聊 | 一次性工具 |

### 3. 信任设计

AI 输出会错，UI 要诚实：

- 标明"可能出错"（别假装权威）
- RAG 场景展示来源（引用让用户可核对）
- 危险操作确认（Day 16 写 tool 要确认）
- **不要用假进度骗"已思考 12 秒"**——除非真实发生了那么多步

### 4. 空态与第一次成功

首屏：**1 个主输入 + 2–4 个示例问题**，胜过功能看板。让用户第一次就成功（示例问题是你精心挑的、保证答得好的）。

对照 Lab-Studio 设计克制：一屏一事。别首屏就堆"模型切换/Prompt 模板/历史/导出"。

### 5. 无障碍与性能

- 流式更新的 live region 要小心——每 token 喧读会让屏幕阅读器炸，只喧读完成段
- 键盘可 Stop / 可聚焦输入 / Enter 发送
- 长会话虚拟列表可后期再做，先保证正确

### 6. 失败模式（反模式）

| 反模式 | 问题 |
|---|---|
| 首屏功能看板 | 用户不知道干什么，流失 |
| 全堆追问+分支+多模态 | 主路径被埋，复杂度爆 |
| 假进度条 | 信任损耗 |
| 引用但不展示来源文件 | 信任没建立 |
| 每次都强吸底 | 用户没法阅读上翻内容 |

## 动手练习（30–40 min）

1. **竞品速拆**：任选 ChatGPT / Cursor Chat / 一个国内助手，列出它的 5 个交互模式，标哪些是主路径、哪些是增强。
2. **线框**：为"Lab 文档问答"画线框——首屏、回答中（带工具进度）、带引用的完成态。
3. **做减法**：删掉线框里至少 2 个"想加但非必须"的功能，写删因。对照 Lab-Studio 的克制看是否协调。
