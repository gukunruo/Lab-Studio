# Day 15 · Agent vs Workflow 决策

> Phase 2 · 编排与 Agent · ~60 min  
> 标签：`agents` `workflows` `architecture` `decision`  
> 前置：Day 13（LangChain）、Day 14（LangGraph）  
> 定位：不是所有智能都该上 Agent。建立"单次调用 / Workflow / Agent"三档决策树。

## 今日目标

建立决策树：何时固定 Workflow、何时开放 Agent、何时只做单次 LLM（Large Language Model，大型语言模型）调用。能识别"为了 Agent 而 Agent"的陷阱，写出团队的默认档位原则。

## 为什么重要

Agent 很酷，但**贵、慢、难测、概率性失败**。很多业务用"确定性流程 + 局部 LLM"更稳更省。用错档位 = 要么过度工程（一个分类任务上 Agent 循环），要么不够（该探索的任务写死流水线）。这课是 Day 13/14 框架工具的**用法决策层**。

## 核心概念

### 1. 三种档位

| 档位 | 形态 | 成本 | 可预测性 | 例子 |
|---|---|---|---|---|
| **A. 单次调用** | 一问一答 / 一次抽取 | 低 | 高 | 文案润色、分类、结构化抽取 |
| **B. Workflow** | 预定义步骤，步骤内可 LLM | 中 | 中高 | 检索→生成→引用检查→校验格式 |
| **C. Agent** | 模型自选下一步 | 高 | 低 | 开放性排障、多工具探索任务 |

### 2. 决策信号

偏向 **Workflow** 当：

- 步骤几乎固定（你能预先画出图）
- 合规要审计每一步
- 要稳定延迟与成本（用户体验可预期）
- 工具副作用大（确定性路径更安全）

偏向 **Agent** 当：

- 路径组合爆炸，写死图不现实
- 任务开放（"帮我调研这个库""查清这个 bug 根因"）
- 可接受失败重试与更高成本
- 有明确终止条件 + 步数上限（否则别上）

偏向 **单次调用** 当：

- 无外部知识、无工具
- 上下文一次塞得下
- 输出简单（分类、抽取、改写）

### 3. Agent 的真实成本（量化）

Day 03 讲过 Agent 放大倍数。这里给直觉：一个 Agent 跑 10 步，每步调一次模型 + 可能调 tool → 等于单次调用的 **20–40 倍 token + 10 倍延迟**。且因为概率性，同样输入两次结果可能不同——**测试要靠 Day 21 的评测集，不是单元测试**。

### 4. 混合才是常态

真实产品常是**外层 Workflow + 内层局部 Agent**：

```
外层 Workflow（固定）：检索 → [内层 Agent：有限工具循环 ≤5 步] → 校验 → 输出
```

外层保证可预测、可审计、成本可控；内层只在真正需要探索的环节放开。

### 5. 与 Day 13/14 的关系

- **Day 13 LangChain** = Workflow 的组件与链（直线管道）
- **Day 14 LangGraph** = Agent 的图与状态机（带循环分支）
- 两者都只是工具——**先决定档位，再选工具**，别反过来

### 6. 产品话术陷阱

"我们做了 Agent" ≠ 用户更爽。用户要的是**正确、快、可预期**。架构是手段。能被单次调用解决的，别上 Workflow；能被 Workflow 解决的，别上 Agent。**默认从最轻档位开始，不够再升级**。

3. **团队原则**：写 3–5 行原则——默认用哪一档、升级条件是什么、何时禁止上 Agent。
