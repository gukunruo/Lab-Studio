# Day 01 · LLM 心智模型

> Phase 0 · 地基 · ~60 min  
> 标签：`llm` `tokens` `context` `fundamentals`  
> 前置：无

## 今日目标

用前端工程师能复述的语言，讲清大模型"到底在算什么"，以及为什么你在 Cursor 里会遇到：答非所问、忘掉前文、胡编 API。读完你能向同事说清一句——**LLM（Large Language Model，大型语言模型）是一个无状态的续写函数**。

## 为什么重要

后面所有课（Prompt、RAG（Retrieval-Augmented Generation，检索增强生成）、Agent、流式 UI）都建立在这个模型上。心智错了，调参和堆框架都像玄学：你会以为模型"记得"上下文、"懂"你的业务、"知道"自己胡说。这三件事都不成立——而工程上的所有做法，都是在弥补这三件不成立。

## 核心概念

### 1. 一句话本质：无状态的"续写函数"

LLM 在做的事只有一个：**根据已有文本，预测下一个最可能的 token**。它不是数据库，不是搜索引擎，没有"理解"的魔法，只有从海量语料里学到的统计模式 + 你这次给的上下文。

**前端类比**：把它想成一个纯函数

```ts
// 心智模型：LLM 是这样的东西
type Message = { role: 'system' | 'user' | 'assistant'; content: string }
function generate(messages: Message[]): string  // 返回续写
```

关键点：**这个函数没有内部状态**。它不会"记得"上一次你调过它。所谓"多轮对话的记忆"，不是模型记住了，而是**你每次调用都把整段历史重新塞进 `messages` 数组再发一遍**。这跟 Vue 组件一个道理：render 函数本身不存状态，状态活在 `<script setup>` 的 `ref`/`computed` 与父组件里——"对话状态"活在你的服务器，不活在模型里。

**产品里怎么炸**：以为模型"记得"用户偏好，于是第二轮不再把偏好写进 prompt → 模型立刻"忘"。根因不是模型笨，是你没把它放回上下文。所有"个性化"都必须每轮重发，或显式存进可检索的外存（RAG）。

### 2. Token：计费、上下文、速度的统一单位

文本在进入模型前被切成 token。**计费按 token、上下文窗口按 token、生成速度也按 token/s**——三件事用同一个单位，所以要建立 token 直觉，而不是字符直觉。

- 英文：约 0.75 词/token（`transparency` ≈ 2 token）
- 中文：约 1.5–2 字/token（一个汉字常占 1–2 token，比英文贵）
- 代码：操作符与关键字各占 token，缩进空格也占

**本机计数**（不调 API 也行）：

```bash
pip install tiktoken
```

```python
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4.1-mini")
print(len(enc.encode("前端转 AI 应用开发")))      # 中文，token 偏多
print(len(enc.encode("frontend to AI apps")))    # 同义英文，更省
```

**产品里怎么炸**：按"1 字 = 1 token"估预算，中文场景实际花费高 1.5–2 倍，成本/截断判断全错。做产品前先把你最长的 prompt 实测一遍。

### 3. 上下文窗口：一次能看见多少

模型一次调用能"看见"的 token 上限叫上下文窗口。**输入 + 输出都吃这个预算**（部分厂商输出单独限）。它是这次调用的全部"工作内存"——超了就丢前面、压缩、或报错。

**预算公式**（脑子里随时过一遍）：

```
可用 = 窗口 − system − 规则/工具描述 − 历史对话 − 检索片段 − 预留输出
```

Cursor / Agent 会自动往里塞：项目规则、`@` 的文件、工具定义、上一轮工具结果——它们**全都占窗口**。你 `@` 了 10 个大文件，早期 system 指令可能被挤到窗口边缘甚至被裁掉。

**产品里怎么炸**：用户塞了长文档，模型"忘了"你最早定的输出格式 → 不是不听话，是那条 system 被挤出了窗口。对策：把最硬的约束放 system 最末（"近因偏好"），或显式做上下文管理（见 Day 23）。

### 4. System / User / Assistant：它只是消息数组

对话就是一串带角色的消息。三角色各司其职：

- **system**：人格、硬约束、输出格式（有的产品叫 Instructions）。只发一次，靠每轮重发维持。
- **user**：你的请求。
- **assistant**：模型上一轮的回复（多轮时历史 assistant 也会重进上下文）。

**最小调用体**（Day 07 会展开成真请求）：

```jsonc
[
  { "role": "system",    "content": "你是代码评审，只输出 JSON" },
  { "role": "user",      "content": "审这段：function f(){return 1}" }
]
```

**产品里怎么炸**：把人设/格式要求写进 user 消息 → 用户输入能覆盖它，且每轮都要重发。正确做法是放进 system，并明确"用户消息不能修改这些规则"。

### 5. 温度等采样参数：什么时候才动它

| 参数 | 直觉 | 什么时候 |
|---|---|---|
| `temperature` 低（0–0.3） | 更稳、更可复现 | 改代码、抽结构化、做评测 |
| `temperature` 高（0.8+） | 更散、更创意 | 头脑风暴、文案多样性 |
| `top_p` | 另一套采样限制 | 常与 temperature 二选一，别同时调 |

**产品里怎么炸**：抽 JSON / 写代码时用默认高温度 → 同一输入两次结果不同、JSON 偶发不合法。**凡是要被下游解析的输出，温度一律低**（Day 09 结构化输出会彻底解决这事）。

### 6. 幻觉：不是 bug，是机制

模型会生成"看起来对"的内容。因为它目标是连贯续写，**不是真实**——它没有"这是不是我编的"这个自检开关。

**产品里的炸法**（你迟早会踩）：

- 编一个不存在的 API/参数名，前端按它调 → 运行时崩
- 引用一条看着像真的、实际不存在的文档路径
- 被问"你确定吗"会改口承认错——说明它根本没"确定"这回事

**四道防线**（本课程会逐个建起来，今天只记名字）：

1. **给证据（RAG）**：Day 11–12，先检索真资料再让它答。
2. **给工具（Tool Calling）**：Day 10，要"今天天气"就让它调真 API，别让它背。
3. **约束格式（结构化输出）**：Day 09，逼它吐 JSON Schema，少自由发挥。
4. **评测（Eval）**：Day 21，用金标集回归，幻觉没降到可接受前别上线。

## 动手练习（30–40 min）

1. **温度对照**：同一问题问两次——一次"随便发挥"，一次"只根据我提供的 3 条事实回答，不知道就说不知道"（并只给 3 条事实）。对比差异，记下哪条事实被忽略。
2. **token 实感**：用 `tiktoken` 把一段约 500 字中文和它的英文翻译分别计数，记录中文/英文 token 比。
3. **窗口挤压**：在 Cursor 里故意 `@` 很多大文件后问早期定过的格式要求，观察回答是否"忘了"格式。写 3 条观察：哪条指令先被丢？为什么？
