# Day 23 · Context 管理与长对话

> Phase 3 · 产品与工程 · ~60 min  
> 标签：`context` `memory` `summarization` `token-budget`  
> 前置：Day 01（上下文预算公式）、Day 11（RAG 检索）、Day 22（成本）  
> 定位：历史越长越贵越超窗口，怎么裁剪、摘要、外存。Day 01 埋的预算公式今天兑现。

## 今日目标

理解长对话为什么必须主动管理上下文、会用裁剪+摘要+检索式记忆三种策略、知道每种策略丢什么信息、能把"上下文预算"做成运行时决策。

## 为什么重要

Day 01 讲了上下文窗口有限 + 预算公式。但真实产品里对话越拖越长：10 轮后历史几千 token、Agent 每步工具结果又堆进来——超窗口就丢早期指令（"忘了"格式要求）、成本随历史线性涨、延迟也涨。**不做 context 管理 = 长对话必崩 + 账单必爆**。

## 核心概念

### 1. 为什么必须主动管

- **超窗口**：历史 + 检索 + 工具结果超了 → 早期 system 被挤掉 → "忘了"约束
- **成本线性涨**：每轮重发全部历史，第 N 轮成本 = 历史长度 × 1 + 新增
- **延迟涨**：input token 越多，TTFT（Time To First Token，首 Token 延迟）越高
- **Agent 更严重**：每步工具结果全进历史，累积爆炸

**前端类比**：像 Vue 组件响应式 state 越堆越多——不做 `shallowRef`/`computed` 惰性化或虚拟列表，越长越卡。Context 管理就是给对话"虚拟化 + 垃圾回收"。

### 2. 上下文预算（运行时决策）

每次调用前先算（Day 01 的公式，现在兑现）：

```
可用 = 窗口 − system − 当前检索片段 − 预留输出 − 工具描述
留给历史的预算 = 可用 − 上面已占
```

历史超了"留给历史的预算" → 触发裁剪/摘要。

### 3. 策略 A：裁剪（最简单）

保留 **首轮 system + 最近 N 轮 + 关键约束**，丢中间。

```python
def trim_history(history, max_turns=6, keep_system=True):
    sys = [m for m in history if m["role"] == "system"] if keep_system else []
    convo = [m for m in history if m["role"] != "system"]
    return sys + convo[-max_turns * 2:]   # 每轮 user+assistant 两条
```

**丢什么**：中间轮次的细节。**风险**：丢了用户早期说的偏好/约束 → 模型"忘"。

### 4. 策略 B：摘要压缩

把旧历史用**小模型**摘要成一段，替换原始历史：

```python
def summarize_old(old_messages):
    summary_prompt = f"把以下对话摘要成关键事实与用户偏好，简洁：\n{old_messages}"
    return llm_small.invoke(summary_prompt)   # 用轻量模型省成本
```

新上下文 = `system + 摘要 + 最近N轮`。

**丢什么**：细节，但保留要点。**风险**：摘要漏了某个关键事实 → 模型答不出。

### 5. 策略 C：检索式记忆（最强大）

把历史**存到外存**（DB/向量库），每轮按当前问题检索相关历史片段塞回——**RAG 思路用于记忆**。

```
全部历史 → 存外存 → 当前问题 embed → 检索相关历史片段 → 塞回上下文
```

- 优点：不超窗口、不全丢、能跨会话记
- 成本：要建索引 + 检索；架构复杂
- 这是"长期记忆"的标准做法，呼应 Day 11 的检索思路

### 6. 工具结果压缩

Agent 的 tool 结果常极长（如 API 返回大 JSON）。策略：

- 截断 + 标注"（已截断，完整见 trace_id）"
- 摘要（"检索到 5 篇相关，主题是 X"替代原文列表）
- 只留结构化关键字段

**别把整段 tool 原文留在历史**——它是上下文与成本的双杀手。

### 7. 三策略对比

| 策略 | 复杂度 | 信息损失 | 适用 |
|---|---|---|---|
| 裁剪 | 低 | 中（丢中间） | 短会话、约束稳定 |
| 摘要 | 中 | 中（摘要漏要点） | 中等会话、要保留偏好 |
| 检索式记忆 | 高 | 低 | 长会话、跨会话、个性化 |

**混合是常态**：最近 N 轮原样 + 更早的摘要 + 关键历史存检索外存。

### 8. 失败模式

| 症状 | 多半是 |
|---|---|
| 长对话后"忘了"格式约束 | 裁剪丢了早期 system，或 system 没固定重发 |
| 成本随轮次线性爆 | 没裁剪/摘要，全量重发历史 |
| 摘要后答不出旧事实 | 摘要漏了关键点 |
| Agent 越跑越慢 | tool 结果原文留历史，累积爆炸 |
| 跨会话"不记得我" | 没用检索式记忆 |
